Esquema de base de datos (borrador)
-- profiles: extensión de auth.users
profiles (id uuid PK → auth.users, display_name, avatar_emoji, created_at)
-- diary_entries: núcleo del diario
diary_entries (
  id uuid PK,
  user_id uuid FK → profiles,
  content text,
  mood text,           -- emoji, ej. "😊"
  entry_date date,     -- para calendario (default: hoy)
  created_at, updated_at
)
RLS: cada usuario solo lee/escribe sus filas en diary_entries y su fila en profiles.

Auth: email + contraseña (mínimo viable); magic link u OAuth se pueden añadir después sin romper el diseño.

Decisiones explícitas para preservar el diseño
No sustituir Navigation por rutas URL (a menos que lo pidas).
AuthView como pantalla full-screen con el mismo gradiente de fondo que App.tsx, no un modal genérico.
Los cambios en vistas serán sobre todo sustituir constantes por estado + fetch; mismas clases Tailwind y estructura JSX.
EntriesView: conectar el botón "Guardar entrada" a insert en Supabase y refrescar la lista.
Stats duplicados (Home + Profile): centralizar en useDiaryEntries o helpers para no divergir.
Nota sobre src/app/main.tsx
En el repo, el bootstrap está en src/main.tsx. El plan asume modificar ese archivo, no crear src/app/main.tsx, para no duplicar el entry de Vite.

Cuando quieras implementar, el siguiente paso sería: definir si prefieres solo email/contraseña o también magic link, y luego aplicar migración + código en el orden: cliente → auth → entradas → vistas. ¿Seguimos con eso?
